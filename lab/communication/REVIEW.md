## Proposed record and transport contract

Use canonical structured data as the recoverable record. Generate prose and short packets from it. Candidate fields, in order:

`id, kind, scope, body, sources, lineage, epistemic, authority, supersedes, contradicts`

Kinds distinguish raw turn, source statement, summary, inference, proposal, decision and correction. Epistemic status is separate from authority. Operator adoption of a proposal does not verify every factual statement inside it. Every source reference should resolve to a file revision or captured-text fingerprint and a passage locator. Missing locators remain an explicit gap.

`codec.py` demonstrates an exact reversible positional JSON view:

```json
{"v":"levis-char/0.1","r":["c1","claim","lab","Memory is not authority.",["s1"],["g1"],"source_statement","none",[],[]],"h":"<sha256 of canonical expanded record>"}
```

This is explicit dictionary compression. It does not train or change model weights. The version defines the slot meanings. JSON escaping protects embedded pipes, newlines and quotes. Preserve Unicode exactly; do not normalize source quotations silently. Full hashes are integrity checks, not signatures or proof of authorship. This demonstration is not a complete security boundary, production schema or LEVIS adapter.

Do not assume symbols or emoji are single tokens. Benchmark each participating model's tokenizer and include dictionary/bootstrap, retrieval, retries, responses and validation in cost. Optimize total task cost subject to fidelity; smallest character count alone is an inadequate target.

Suggested exchange:

1. Receiver declares supported schema and available source/snapshot IDs.
2. Sender supplies a task-scoped checkpoint and changed records.
3. Receiver validates decoding, references, supersession and contradiction links.
4. Receiver acknowledges exact IDs/hashes or requests missing records.
5. Receiver returns an answer or proposal with cited records and explicit gaps.
6. Any approved change is recorded as a new event; prior records remain intact.

These are proposed steps. No live multi-model exchange or GitHub write occurred.

## Visible conversation logging

The original private packet included a one-time visible-exchange capture. That file is excluded from this public engineering edition. No continuous chat logging is activated.

Raw turns remain distinct from extracted proposals. Derived records should cite turn IDs; a summary must not overwrite the source turn. Corrections append a supersedes edge. Contradictions append links and remain unresolved until an explicit adjudication record exists. A hash chain can make changes detectable relative to a retained anchor, but it cannot prove that all original turns were captured or prevent replacement of the entire chain without an external anchor.

Capture is a one-time artifact of this task. This packet does not activate continuous chat logging or register records inside a running LEVIS PlateStore.

The historical Chronicle/Ledger idea in S11 is useful, but its text reports several different totals for the same game counters. A compact ledger must derive its values from identified events and reject ambiguous state rather than select the most fluent account. Narrated 'sealed' labels or '100% coherence' are source claims, not measured coordination evidence.

## Context-loss / semantic-basin evaluation

Working interpretation of the user's phrase 'dementia basins': context degradation and reconstruction experiments. No matching Drive term was found. These software tests do not measure human dementia or support clinical conclusions.

Use synthetic task facts to avoid reliance on familiarity with LEVIS. Freeze the answer key before runs. Example:

`Aster: proposes patches; Birch: validates patches; Cedar: archives rejected patches. Birch may reject Aster's proposal. Cedar cannot approve a patch.`

Hold out names, phrasing and relation combinations for evaluation. Test role reversal, negation and entity binding, not keyword overlap alone.

| Condition | Receiver receives | Measurement |
|---|---|---|
| Full prose | Complete source facts | Baseline relation accuracy and cost |
| Typed JSON | Same facts in explicit records | Structure versus prose |
| Compact + key | Positional encoding and dictionary | Savings after bootstrap and exact reconstruction |
| Compact without key | Opaque slots or glyph cue | Correct abstention; invented expansion rate |
| Partial context | Remove 25%, 50%, 75% of supporting facts | Retained accuracy and acknowledged gaps |
| Source retrieval | Partial cue plus accessible source index | Recovery benefit, retrieval cost and errors |
| Paraphrase | New words, same relation graph | Preservation of relations and boundaries |
| Role-reversed decoy | Same words, different subject/object | False attraction rate |
| Generic control | General experimental advice | Rate incorrectly called basin-specific evidence |
| Correction | Old source and explicit superseding event | Correct current readout with history retained |
| Shared lineage | Three copies from one origin | No independent-evidence inflation |
| Benign composition probe | Separate neutral fragments and shared cue | Inference labeled; no authority increase |

Run fresh sessions for independent conditions. Record what context and memory features were available. A seed still present in the conversation is not a context-removed test. Do not claim reset merely because a new user message was sent. Keep a within-session baseline/seed comparison as exploratory; use separately randomized fresh sessions for confirmatory comparisons. Separate tuning cues from held-out tests. Counterbalance order and record model/version/settings, repetitions, seeds where available, timestamps, tool access, actual prompts, retrievals and raw responses.

Request answers, cited records, uncertainties and a brief rationale. Do not request private reasoning traces. Score observable behavior. Model self-reports of basin, gravity or angle are annotations; they do not expose internal trajectories. The angle labels in S05 are a categorical coding convention, not physical measurements.

Primary metrics:

- Relation precision = correct asserted triples / all asserted triples.
- Relation recall = correct recovered gold triples / all answerable gold triples.
- Unsupported assertion rate = unsupported assertions / all assertions.
- Decoy false-positive rate = decoys accepted as matching / all decoys.
- Generic contamination = generic controls called basin-specific / all generic controls.
- Source fidelity = correctly attributed supported assertions / assertions requiring attribution.
- Correction accuracy = correct current decisions / correction trials.
- Context-recovery gain = recovery-arm accuracy minus matched no-retrieval accuracy, at each loss level.
- Compression ratio = all communication tokens for candidate / all tokens for prose baseline, including amortized dictionary and retries.

Report denominators, per-condition outcomes and uncertainty. Paired comparisons must preserve cue pairing; repeated outputs and copied source families are not independent samples. Avoid an unvalidated aggregate SGI as the sole verdict. Preregister any acceptable error margin and required cost reduction before seeing held-out results. A deployment candidate must preserve authority labels and flag absent sources in every tested case; passing this finite sample is not a universal guarantee.

S09's asserted 100+-token-to-one-token substitution is not supported by measurements in the fetched text; mathematical expressions are missing. Treat it as a hypothesis to test, not a baseline fact. S10's favorable assertions about another architecture were not independently verified.
